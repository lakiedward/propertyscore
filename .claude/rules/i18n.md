# Internationalisation rules (Romanian and English)

## Basics

- Two languages: `ro` (default, source and `fallbackLng`) and `en`. Every user-visible string, `aria-label`, `title`, `placeholder`, toast, page title and validation message goes through `t()`. `eslint-plugin-i18next` rejects literal strings in JSX.
- The same change adds the key to `src/i18n/locales/ro/<namespace>.json` and `src/i18n/locales/en/<namespace>.json`. Write Romanian first. If a translation is uncertain, say so in the PR description; never leave a key out or copy the other language in.
- `pnpm i18n:check` must pass: same files and keys, same `{{placeholders}}`, no empty values, no cedilla `ş` / `ţ` in Romanian.
- Not translated: user-entered content, log and Sentry messages, URL paths, database enum codes, `AppError.message`.

## Namespaces and keys

- One namespace per feature (`properties`, `auth`) plus `common` for shared actions, `errors.<AppErrorCode>`, `validation.*` and generic words. Components call `useTranslation('<feature>')` and reach shared keys with the `common:` prefix.
- Keys are semantic, nested `camelCase`, grouped by screen or component then element: `properties:form.title.label`, `properties:list.empty.title`, `common:actions.save`. Never an English sentence as a key.
- Keys are type-checked through `i18next.d.ts`; a missing key is a build error. Never cast a key to silence the check. Dynamic keys are built only from typed unions (`t(`common:errors.${error.code}`)`, `t(`properties:type.${property.type}`)`).
- Enum labels live under the feature namespace keyed by the database code (`properties:type.apartment`, `properties:status.archived`).

## Writing strings

- Whole sentences with interpolation; never concatenate translated fragments (`t('deleteConfirm', { title })`, not `t('delete') + ' ' + title`). Romanian word order and agreement differ from English.
- Embedded links or emphasis use `<Trans>` with named components; never split a sentence around a `<Link>`.
- Plurals always pass `count` and use i18next suffixes. Romanian needs `_one`, `_few` and `_other` (`1 proprietate`, `2 proprietăți`, `20 de proprietăți`); English needs `_one` and `_other`. Never choose a plural form with an `if`.
- Romanian uses ș / ț with a comma below (U+0219, U+021B), never ş / ţ with a cedilla, and Romanian quotation marks „…”.
- Romanian text runs 20–30% longer: never fix the width of buttons, badges or table headers; check new screens in Romanian first.

## Formatting

- Dates, numbers, percentages and money only through `@/i18n/format` (`formatDate`, `formatDateTime`, `formatRelative`, `formatNumber`, `formatPercent`, `formatCurrency`, `formatPrice`, `parseLocaleNumber`). `formatPrice` shows whole amounts as people read prices (`125.000 €`, `500 lei` in Romanian; `€125,000`, `RON 500` in English); `formatCurrency` keeps decimals for invoices and totals. Never `toLocaleString()`, `toFixed()` for display, or a new `Intl.*` object in a component.
- Formatting locales: `ro` → `ro-RO`, `en` → `en-GB`.
- The currency comes from the record (`RON` / `EUR`), never from the language.
- Dates are stored as `timestamptz` and shown in the browser's time zone. The shadcn `Calendar` receives the `date-fns` locale (`ro` / `enGB`) and `weekStartsOn: 1`.
- Client-side text sorting uses `Intl.Collator` for the current locale.

## Language switching and detection

- Detection order: `profiles.locale` → `localStorage` `locale` → `navigator.languages` (`ro*` → `ro`, `en*` → `en`) → `ro`. It lives in `i18n.ts`; no detector plugin.
- The switcher (header and login page) labels options in their own language with a `lang` attribute, calls `i18n.changeLanguage`, writes `localStorage`, updates `profiles.locale` when signed in, and relies on the `languageChanged` handler to set `<html lang>` and the Sentry tag.
- No URL language prefix for authenticated routes.

## Third-party text

- shadcn/Radix primitives ship hidden English strings (the `sr-only` "Close" in `Dialog` and `Sheet`, pagination labels, "Toggle" texts). Replace them with `t()` when the component is added.
- Supabase error messages are never shown; `toAppError()` maps their codes to keys.
- Auth email templates in `supabase/templates/` carry both languages; change both branches together.
